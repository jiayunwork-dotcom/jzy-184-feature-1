# 设计说明：玉米生育期积温预测服务

本文说明服务在四个需要取舍的点上的选择与理由：日积温口径、缺测补值、
增量重算与快照、事件与并发。代码按职责分包：

| 包 | 职责 |
| --- | --- |
| `internal/gdd` | 日积温三种口径（平均、单正弦、单三角），纯函数 |
| `internal/fill` | 缺测日补值（邻站观测 + 海拔修正，回退气候平均） |
| `internal/cum` | 逐日累计与生育阶段日期推算 |
| `internal/ensemble` | “往年试走”：年份合格判定、逐日积温试走、分位/最早最晚/比例统计（纯函数） |
| `internal/engine` | 写入仲裁、补值编排、增量重算、快照、变更事件、历年试走编排（不依赖数据库） |
| `internal/store` | 上述接口的 PostgreSQL 16 实现（事务、咨询锁、SQL） |
| `internal/enginemem` | 内存事务实现与“全量从头重算”参考器（含历年试走参考实现），供测试对照 |
| `internal/api` | Gin 路由、参数解析与统一响应 |
| `internal/model` | 共享数据结构 |
| `cmd/server` | 启动入口：迁移 → 全量对齐 → HTTP |

## 1. 日积温口径

### 默认口径：单正弦、基点与上限双截断

假设一天的温度关于半日呈正弦，
`T(t) = m + a·sin(t − π/2)`，`m=(tmax+tmin)/2`，`a=(tmax−tmin)/2`，
对 `max(min(T, upper) − base, 0)` 在一日上积分取平均。解析解为
“高于基点的积分减去高于上限的积分”，其中温度高于阈值 `c` 的日平均为

```
∫max(T−c,0)dt / 2π = (m−c)/2 − (m−c)·φ/π + a·cos(φ)/π,   φ = asin((c−m)/a)
```

选它做默认的理由：

- 最低温低于基点的日子很常见（春秋夜间）。平均法把夜间低于基点的温度
  当作“负积温”去抵消白天的热量，系统性低估；正弦法只积分温度真正高于
  基点的时段，更接近当日实际累积热量。
- 最高温超过上限时，双截断能剔除高温胁迫时段的虚高积温；平均法不做上限
  截断，热浪天会高估。
- 只需 `tmax/tmin` 两个已有输入，解析解无逐时循环，计算量与平均法相同。

### 与平均法在哪些天差得多

记平均法 `GDD_mean = max((tmax+tmin)/2 − base, 0)`。两种口径在
“最高最低都落在 `[base, upper]` 内”时**完全相等**（此时逐时截断不改变
曲线，正弦积分退化为均值减基点）；差异只出现在边界穿越的日子：

1. **`tmin < base < tmax`（夜间穿基点）**：正弦法 > 平均法，且最低温越低、
   最高温越接近基点，差异越大。例：`base=10, tmax=25, tmin=5`，
   平均法给 5，单正弦给约 7.1。春播出苗期此类天气最多，直接影响出苗/拔节预测。
2. **`tmax > upper`（白天穿上限）**：双截断口径 < 平均法；全天高于上限时
   积温被截成常数 `upper−base`。
3. **`tmax <= base`**：两种口径都为 0，无差异。

单三角近似（`triangle`）语义相同，只是把正弦换成两段直线；平均法
（`mean`）保留供习惯老算法的站点对比，地块可按品种/地块选择口径。

### 口径共同保证（`internal/gdd/gdd_test.go`）

- 最高最低都在基点与上限之间时，三种口径都等于平均温度减基点
  （基点 10、最高 30、最低 14 → **12**）；
- 最高温不超过基点时为 0；
- 任意输入不为负；
- 基点调高，日积温只减不增——因此累计曲线不增，各阶段日期只推迟或不变
  （另有端到端的基点单调性测试）。

## 2. 缺测补值

默认策略为**邻站优先、气候平均兜底**：

1. 取当天有真实观测、海拔差不超过 800 m、大圆距离最近（≤80 km）的邻站；
2. 按环境直减率 0.0065 ℃/m 修正：
   `T_target = T_donor + 0.0065·(elev_donor − elev_target)`；
3. 无可用邻站时回退本站历年同日（DOY，闰年 2/29 回退 3/1）的气候平均；
4. 两者都没有就**不编造**：该日标 `missing`、积温记 0。

理由：县域几十个自动站间距几公里到几十公里，同一天气过程同步，同日邻站
观测能反映当天冷暖异常，而气候平均只是“平常那一天”；海拔修正避免山地站
的系统温差。区域性断网（邻站也缺）时退到气候平均，保证序列连续、可外推。

补值行带 `source=filled` 与 `fill_method/fill_from` 标记。真实数据到达后，
该站日胜出观测变化会触发重算（见下节），补值被自动替换为 `observed`。

阶段预测时，`asOf`（今天）之前用观测或补值，之后用本站气候平均外推，
窗口 270 天（覆盖玉米全生育期）。达到阈值且日期不晚于 `asOf` 的阶段标
`reached` 并给实际达到日期；更晚的标 `forecast` 给预计日期。

## 3. 增量更新为什么和全量重算一致

### 快照方案：逐日累计即快照

`plot_daily` 每地块每天一行，除当日温度/日积温外还存**累计积温**，本身
就是逐日快照。另存 `plot_stages`（每地块每阶段一行当前结果）。

一条观测/更正只影响一个**站日**。而某地块某天的日积温只取决于：

- 当天该地块生效绑定站的观测，或
- 当天各邻站观测（仅当绑定站缺测时），或
- 该站该日序气候平均。

**不依赖任何其他日期的数据**（积温是逐日相加，没有跨日热量惯性）。
因此变化日为 `d` 时，受影响地块 `d` 之前的行完全不变；`d` 及以后累计值
需要顺延。重算过程：

1. 读出该地块 `d` 前一天的累计值作为种子（播种日当天或没有更早行时为 0）；
2. 删除 `plot_daily` 中 `date >= d` 的行；
3. 从 `d` 到 `asOf+270` 逐日重建，当天及以后累计 = 种子 + 新序列逐日和；
4. 在重建后的完整序列上重新判定 5 个阶段日期，替换 `plot_stages`。

一次批量写入含多个站日时，`from` 取该地块序列内**最早**的变化日。注意
变化站可能不是地块绑定站——其他地块可能把它当邻站补值来源，所以一次观测
写入会检查所有地块（从各自最早变化日起重算）。

**全量重建**的触发：改绑、品种参数/口径/播种日修改、站点坐标海拔变更、
气候平均变更——这些可能影响任意历史日或补值选择，对相关地块从播种日重建，
种子为 0。这是有意保守：这类操作频率低，正确性优先。

### 空间与重算成本的权衡

没有额外的“检查点”表：每个地块每天本来就要存一行逐日积温（曲线查询需要
它），累计值只是同表一个字段，等于**零额外空间**拿到了密度为“每天一个”
的检查点。更正某天的成本是 `O(窗口剩余天数)`（最多约 270 行/地块），与
“从播种日算起”相比，晚期更正（比如 6 月更正 4 月某天）能省掉播种日到
变化日之间整段的重建。若未来地块数很大，可再按周或按旬稀疏化重建——但
当前规模（县级几十站、地块量级有限）每日快照最简单且必然正确。

### 一致性是怎么保证的

- 写入仲裁、快照替换、阶段替换、事件插入在**同一个数据库事务**内提交，
  崩溃整体回滚，不存在“观测改了但地块没重算”的中间态；
- 阶段结果始终由“完整快照序列”重新判定，而不是在旧阶段上打补丁；
- `enginemem.ReferenceDaily` 是一份完全独立的参考实现：不读任何快照，
  只用最终观测表、绑定、气候平均从播种日逐日算。随机测试每一步都把
  增量结果与它逐日比对；`internal/store` 的 PG 集成测试把同一随机序列
  分别打到 PG 与内存两个后端互相核对。

## 4. 事件

阶段日期一旦变化写一条 `stage_events`：原日期、新日期、原/新状态、
触发原因（站号+日期）、`change_id`。幂等键
`event_id = 地块:阶段:change_id`，数据库唯一约束保证：

- 同一次批量数据变化（共用一个 `change_id`）对同一地块同一阶段至多一条；
- 重放/重启对齐（`Recover`）在数据未变时不产生重复事件——参考结果与
  现有阶段行相同，比对无差异即不写。

小程序用 `GET /api/v1/events?after_id=&limit=&plot=` 按自增 ID 游标拉取。

## 5. 并发与重启续跑

- 同站日并发：写事务内先对涉及站代码排序后依次执行
  `pg_advisory_xact_lock`（FNV 哈希为 bigint），同站写入被序列化，
  大序号最终胜出；序号小的晚到记录进 `observations_stale` 存档不参与计算。
  同批多条同站日记录先在应用层折叠为序号最大的一条。
- 重启：数据与结果的修改同事务提交，未提交的更新回滚后客户端可整体重发
  （接口对完全重复上报幂等）。服务启动时执行 `Recover`：对所有地块用最终
  数据从播种日全量重建一次并推进 `as_of`，兜住任何中断并让预测随日期推进；
  结果与未中断时逐日一致，且不制造重复事件。

## 6. 主要表

`stations`、`varieties`（阈值数组 + 校验约束）、`plots`、
`plot_bindings`（改绑历史）、`observations`（每站日仅胜出行）、
`observations_stale`（被压制记录存档）、`climate_normals`、
`plot_daily`（逐日快照）、`plot_stages`（当前阶段结果）、
`stage_events`（变更事件）。详见 `internal/store/migrations/0001_init.sql`。

## 7. 历年“试走”：年际范围、分位与到达比例

单点预计（§2 末）只给一个“按气候平均外推”的确定日期，对“偏冷偏热差
七八天”没有任何表达。历年试走把各站攒下的多年逐日气温当作彼此独立的
“如果今年像那年”样本，把播种后、尤其 `asOf` 之后的日子各走一遍，给出
每个未达到阶段的**年际分布**，而不是一个点。

### 7.1 输入：按“站 + 年”整年导入、整年替换、整站年原子

- 一次请求可带多个站、多个年；记录逐条校验，非法条逐条给原因，其余
  站年照常进入。非法情形：最低高于最高、温度越出 `[-60,65]`、站点不
  存在、日期不属于所标的年份（`year` 字段缺省时取日期自身年份）、同批
  同站同日重复。
- **一站一年是一个整体**：一个站年内只要有一条非法，整年不生效；合法
  条目回 `ok=true, applied=false` 并注明“被同站年非法记录连累”，非法
  条目回 `ok=false` 带具体原因。再次导入同站同年即**整年替换**。
- 替换在单个数据库事务内“先整段删除、再批量插入”，与提交绑定：
  - 导入途中进程被杀 → 事务整体回滚，重启后仍是旧的一整年，任何读
    事务都查不到“删了旧年、新年只写了一半”的状态（无半年数据）；
  - 同站的导入先取与观测写入同一套按站 `pg_advisory_xact_lock`（站代码
    升序加锁），同站同年两个并发导入被串行化，最终内容**完整等于其中
    一次**，不会混合；跨年/跨站的导入不互斥。
- 历年表 `historical_weather` 与 `observations`/`climate_normals` 完全
  分离，**不参与**任何现有计算路径：导入或替换历年不会重算快照、不会
  产生阶段事件、不改变单点预计与逐日曲线（见 7.6）。

### 7.2 缺日子怎么办：只用本站气候平均顶，不借邻站，缺到底则该年不参与

某个候选年在未来某天没有本站真实记录时：

1. 优先用该站该年该日（按日序对齐，见 7.3）的**真实历年记录**；
2. 缺的日子用该站**历年同日（DOY）的气候平均**顶上（2/29 缺值回退
   3/1，与现有补值/外推同一套回退）；
3. 若该日连气候平均也没有（`historical` 与 `climate_normals` 都缺），
   **不把它当 GDD=0 静默处理，而是判该年整体不合格、不参与统计**；
4. 此外要求每个“绑定站 × 映射日历年”段内至少有一天真实历史记录；
   若某段完全靠气候平均合成（例如改绑后的站该候选年一条记录都没有，
   或该年在跨年段上没有任何数据），该年也不参与——否则它只是把气候
   平均重复一遍，对年际分布零贡献还会把样本撑大。

**为什么不借邻站同年同日**：范围要度量的是“年与年之间的冷暖差异”。
邻站温度同时含年际信号和**站间空间差**（海拔、小气候、地形），借站会
把空间差混进年际差，且不同候选年可借的邻站组合不同，样本不再可比。
本站真实记录缺时，气候平均是唯一一个“同年份、同位置、无空间差”的
无偏兜底。

**代价与宽窄方向**：用气候平均补缺会把该年的冷暖异常在缺日处拉回
“平常那一天”，使该年到达日向中位数收缩。因此：

- 总体上范围会被**压窄**（偏早/偏晚尾都收向中部），分位偏保守；
- 但“缺得多的年直接剔除、不拿 0 或平均硬凑”又避免了两个相反的假性
  偏差：不把缺日当 0（那会虚增很多“窗口内到不了”的冷年假象、范围虚
  宽），也不允许整段合成（那会在中位数处堆一个假样本、范围虚窄）。
- 返回里带 `years`（实际参与年份）与逐年判定，调用方能看到“你给的
  三十来年里到底哪几年参与了”。

### 7.3 候选年份与日对齐

- 候选年取**未来窗口内所有出现过的绑定站“有资料年份”的交集**：改绑
  后要在两个站都有该年记录才让该年参与（配合 7.2 的段内真实日约束）。
- 历史年与本季按**年内日序（DOY）对齐**：本季未来第 *k* 天，取候选年
  第 *k* 天的温度。之所以不按“月/日”对齐，是因为气候平均本身就是
  DOY 序列，而 §测试要求“历史每天都等于气候平均 ⇒ 各分位等于单点
  预计日”——月/日对齐在候选年有/无 2/29 时会让其后整段错位一天。
  本季闰年 2/29（DOY 60）在平年候选年自然落到 3/1（DOY 60），与气候
  平均 2/29→3/1 的回退同口径；候选年是闰年时取到其真实 2/29。
- 窗口与单点预测一致：`asOf .. asOf+270`。跨年时候选年还需要次年的
  记录（DOY 对齐到 `year+1`），缺日按 7.2 处理。

### 7.4 分位口径：反经验 CDF 的次序统计量，且与“到达比例”同一口径

N 个参与年份在某阶段上得到 N 个到达日（窗口内未到的视为 +∞），按
日期升序排列（未到年排在最后、内部按年份排序）。

- **q 分位取第 `ceil(q·N)` 小**（0 起下标 `ceil(q·N)-1`）。该位序上是
  未到年时，如实返回 `reachable=false`、`date=null`——**绝不用最晚日或
  窗口末日顶替**。默认给 0.1 / 0.5 / 0.9（偏早、居中、偏晚）。
- 到达比例查询是同一个经验分布的另一侧：给定日期 `by`，比例 =
  “到达日 ≤ by 的年数 / N”。两者严格配套：`by` 取 q 分位日时比例恰为
  `k/N`（k=⌈qN⌉）。
- 未到年计入 N、计入 `not_reached_years`，不从样本里剔除——丢掉会让
  范围显得比实际窄，也会把分位/比例整体抬高。
- 这个次序统计量定义天然保证题目要求的四条单调性：
  q 不减 ⇒ 日期不减（同日可等）；阶段阈值递增 ⇒ 同 q 跨
  出苗→成熟日期不减；基点调高逐日积温只减不增 ⇒ 任一分位只推迟或
  不变（含从可达变不可达）；比例随 `by` 不减。
- 最早/最晚只在“窗口内到达”的年份里取；全部未到时两者均为空，
  `not_reached_years=N`。

### 7.5 已达到阶段与“给不出范围”

- 阶段是否已达到，直接读现有单点快照 `plot_daily`/`plot_stages` 的
  结论（截至 `asOf` 累计达到阈值）。**已达到阶段不使用任何历年**：
  范围收成实际达到日一天（最早=最晚=各分位=实际日），到达比例在实际
  日之前为 0、当天起为 1。因此导入/替换历年绝不会改动已发生的事实。
- 当一个未达到阶段连一个合格参与年都没有（相关站从没导过历年、候选
  年交集为空、或候选年都因缺日被剔除）时，该阶段 `available=false`
  并带中文原因；若五阶段里至少有阶段能答（早期阶段已达到），顶层仍
  `available=true`，答不了的阶段各自带原因；一个都答不上时顶层
  `available=false`。接口绝不返回“看着正常的空数组”。

### 7.6 与现有功能的边界、一致性

- 历年试走是**只读的实时计算**：每次查询用最终已提交数据（档案、绑定、
  品种、快照、气候平均、历年）现算一遍，不落任何新表、不做增量缓存。
  因此观测补传/更正、改绑、品种参数修改、历年导入/替换无论先后怎样
  交错，范围与比例都逐项等于“只拿最终数据从头算一遍”——和 §3 的一致性
  原则相同，只是这里直接以无缓存实现之。
- 当季 `asOf` 之前的累计积温从现有快照读（与单点、逐日曲线同一序列、
  同一补值/外推口径），各候选年只在其后的日子上分叉；`asOf` 之前已达
  到的阶段按 7.5 收成实际日。
- 录过气候平均的站，单点预测仍按气候平均外推，不因导入历年而改变；
  阶段变更事件一条不多一条不少（历年写入根本不调用重算）。
- `enginemem.ReferenceEnsemble` 是与引擎 `buildEnsemble` 完全独立的
  第二份实现（候选年交集、段划分、DOY 对齐、排序、分位都另写一遍），
  随机交错测试每步把两者逐项对账；PG 集成测试再把同一序列在 PG 与
  内存两后端对账（`TestPGHistoricalRangeParity`）。

### 7.7 接口

- `POST /api/v1/historical/batch`：`records[]`（station_code、year 可空、
  date、tmax、tmin），逐条回 `ok/applied/reason`，并按站年汇总。
- `GET /api/v1/plots/:code/stage-ranges?quantiles=0.1,0.5,0.9&date=`：
  五阶段的 `years_used/years`、`earliest/latest`、`quantiles[]`
  （含 `reachable`）、`not_reached_years`；已达到阶段收成实际日。
- `GET /api/v1/plots/:code/arrival?stage=&by=&date=`：`fraction`
  （0..1）、`years_used`、已达到阶段的 0/1 与实际日。
- 非法查询返回 400：分位不在 `[0,1]`、阶段名不存在、`by` 早于播种日、
  日期格式错误。
